# 设计版本保留规则

每次收录后，旧设计都应继续出现在仓库里，能直接打开预览、下载源文件并继续修改。**迭代采用新的同级目录，旧目录的预览与全部源文件保持原样。** Git 历史方便追溯，但不能替代这里要求的并列保存；只备份旧预览也不能保留其编辑能力。

## 哪些文件能改

| 相对目标分支当前版本的路径 | 要求 |
| --- | --- |
| 已存在的 `designs/<方案>/preview.png`、`source/`、`previews/` 等 | 不得修改、删除、移动，也不得在旧目录中追加其他文件 |
| 已存在方案的根 `designs/<方案>/README.md` | 可编辑或补充，用于版本导航、说明与来源纠正；不得删除或变成链接 |
| 新的 `designs/<新目录>/` | 可添加完整方案；首次合并前可在同一 PR 中继续修改 |
| 仓库首页、通用文档、模板及工具 | 可正常修改，图库必须保留旧入口并追加新入口 |

更换旧版的字体、随机参数、配置或源图，即使预览看起来没有变化，也属于设计版本变更，需要另建目录。旧版缺少源文件而现在补齐，同样通过一个新完整版本提交，旧版根 README 可链接到它。

## 目录和版本说明

例如从 `designs/03-white-blue-code/` 继续修改：

```text
designs/
├── 03-white-blue-code/
├── 03-white-blue-code-v02-yourname/
└── 03-white-blue-code-v03-anothername/
```

版本号只是便于阅读的标签，目录名必须唯一；多人同时投稿可加自己的 GitHub 用户名，避免重名。新目录应是完整副本，包含预览、说明、全部 `source/`、字体、图层及配置，然后只编辑副本。不得用符号链接、只存一张旧预览或依赖 Git 历史取代完整版本。

新方案 README 和 PR 需写明：版本标签、父版本的目录路径与可点击链接、开始修改时目标分支的完整提交 SHA、修改内容及新旧预览。独立方案父版本写“无”。首页图库保留旧入口，并追加新版本预览和说明；旧版根 README 可以增加“后续版本”链接。

基线 SHA 用来追溯父版本来源。**自动保护使用目标分支当前版本，不使用这个手工填写的 SHA。** 如果 PR 打开后 `main` 收录了别人的版本，先同步最新 `main`，再解决冲突并检查，不能删掉后来新增的目录。一个新目录首次合并前，继续修改同一 PR 中的文件无需再增加版本目录；首次合并后，它就成为受保护的旧版本。

## 提交前检查

从仓库根目录运行（Python 3，无额外包）：

```shell
git fetch origin main
python scripts/check-design-versions.py --base origin/main
```

默认检查当前工作目录，包括未跟踪文件。检查已提交的分支内容时使用：

```shell
python scripts/check-design-versions.py --base origin/main --head HEAD
```

在 fork 中请使用指向原仓库的远程，例如 `upstream/main`。如果目标分支已前进，先将其最新内容合并到自己的分支，再执行检查。检查会限制旧方案目录变更，并验证新方案有常规 `README.md` 文件及带 PNG 文件签名的首图；签名检查不等于完整图像解码，仍需打开图片确认。源文件是否完整、版本关系是否准确、图库和相对链接是否有效仍由投稿者和审核人核对。

GitHub 工作流的检查名为 **保留设计历史**。工作流进入远程仓库并运行后，管理员还需把此检查设为合并必需条件；本地增加脚本、文档或工作流不会自动启用远程保护。见[维护说明](MAINTAINERS.md)。

## 已有 PR 会覆盖旧版怎么办

保留现有 PR，调整该 PR 的分支即可，无需为每次修订重开 PR：

1. 先备份当前修改和未提交文件，确认能重新打开。记下当前 PR 基于哪个方案、哪些文件被改动。
2. 为每个改动过的旧方案准备一个唯一的新同级目录。先将工作分支中该方案的**完整当前状态**复制进去，包括改好的预览和所有源文件；不要只复制差异文件。
3. 对照目标分支最新版本核对两份目录。确认新版副本完整、可编辑且没有遗漏后，才把旧目录恢复到目标分支的当前内容。需要同步目标分支时先保存好副本，并在冲突中保留所有已收录版本。
4. 在新目录完善父版本、基线 SHA、版本标签及贡献记录，修正仍指向旧目录的编辑命令。首页并列链接新旧版本；可在旧版根 README 增加新版入口。
5. 运行版本检查和受影响的渲染命令，确认旧文件不再出现在 PR 的修改或删除列表中，新目录包含完整材料。把这些调整提交到原 PR 分支。

不要在没有备份和核对前批量恢复或删除旧目录，那会丢掉还没移入新版本的工作。若新目录名被另一位同学先合并占用，选择一个新的唯一名称。

## 工具使用约定

具体复制和渲染命令见[修改现有设计](EDITING.md)。旧版本中保存的历史工程教程可能包含默认旧路径，它们用于解释原版本如何制作。继续设计时，以本规则为准：先完整复制，再把命令的输入和输出改到新目录；不得按旧命令回写父版本。仅复现旧版时，输出到本地 `generated/` 即可。
